When **auto-apply is off**, every processed document lands in the **Review** queue instead of
being written straight back. Nothing reaches paperless until you approve it.

<Aside type="note">
OCR text is the exception: when OCR runs it's written back immediately, because it's a
straight transcription, not a reviewable suggestion. Only the metadata waits for you.
</Aside>

## Reviewing a document

Open an item and you get a side-by-side view:

- **Left — the document.** The recognised text, scrollable, so you can check the suggestions
  against the source.
- **Right — the AI suggestions**, each editable before you apply:
  - **Title** — an editable field; the previous title is shown struck through when it changes.
  - **Tags** — one toggle per suggested tag. Keep a tag (✓) or drop it (✗); tags that don't
    exist yet are marked **new**. Your document's current tags are kept.
  - **Correspondent** — editable; defaults to the suggestion, blank for none.
  - **Date** — a date field.

Then choose:

- **Approve & apply** — writes your (possibly edited) values to paperless and removes the
  trigger tag.
- **Reject** — discards the suggestion. The document keeps its trigger tag, so you can change
  a setting and let it run again.

## Bulk approve

From the list you can select several items and **approve the selected** in one go. If some
fail, those stay selected with their error shown, so you can see exactly what didn't apply
and retry just those.

## Switching modes

Auto-apply vs review is a single toggle on the [Processing screen](/docs/processing/#apply).
A common path: start in **review** mode to build trust in the model and your prompts, then
switch on **auto-apply** once the suggestions are consistently good.
